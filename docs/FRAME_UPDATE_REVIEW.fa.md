# گزارش بررسی قاب جدید یاسین

## درخواست و نتیجه

تصویر جدید ارسالی کاربر با ابعاد 592×1024 و قالب عمودی، بدون بزرگ‌نمایی یا بازتولید پیکسلی، جایگزین قاب قبلی شد: `app/src/main/res/drawable-nodpi/mushaf_pistachio.jpg`. فایل PNG قبلی 941×1672 دیگر در پروژه نیست. طرح اصلی، گل‌ها و حاشیه‌های همین JPEG حفظ شده‌اند.

در خواننده، کادر بالایی دو حالت دارد:

| صفحهٔ برنامه | سطر اول داخل کادر | سطر دوم داخل کادر |
| --- | --- | --- |
| صفحهٔ اول یاسین | بسم‌اللهِ دادهٔ `yasin.json` | صفحهٔ ۱ از ۱۰ |
| صفحه‌های بعد | سورة يس | صفحهٔ جاری از ۱۰ |

«فهرست» و «بیشتر» درست زیر قاب بالا هستند تا با متن و گل‌ها برخورد نکنند. پایین صفحه، تغییر صفحه، وضعیت/پیشرفت پخش و کنترل آیه را نشان می‌دهد. دکمهٔ اصلی داخل فضای میانی نقش پایین می‌نشیند؛ دکمه‌های قبل/بعد شفاف‌اند تا تزئینات را نپوشانند. فهرست سوره‌ها نیز همین تصویر و کادر بالایی را استفاده می‌کند.

## جزئیات فنی برای بازبین

- `MushafFrameDrawable.java`: ناحیهٔ بالایی تصویر 0–140، بخش صاف میانی 140–865 و تزئین پایین 865–1024 است. ابتدا و انتهای تزئین بالا تقریباً در مقیاس طبیعی عرض نمایشگر رسم می‌شوند. ارتفاع اضافهٔ ابزار پایین در بخش صاف بالای تزئینات قرار می‌گیرد؛ خود کادر و شاخه‌های پایینی کشیده نمی‌شوند.
- `MainActivity.java`: `updatePlayback` با شرط `page.page()==0` محتوای سربرگ را تنظیم می‌کند و در جابه‌جایی صفحه از طریق دکمه‌ها و انتخاب آیه به‌روز می‌شود. در حالت تمام‌صفحه، ردیف فهرست/بیشتر هم با سربرگ و ابزارها مخفی می‌شود. شمارهٔ صفحه، شمارهٔ داخلی صفحه‌بندی همین برنامه است؛ این صفحه‌ها شماره‌های چاپی مصحف مرجع نیستند.
- `tools/render_preview.py`: یک تصویر سه‌ستونی از فهرست، صفحهٔ اول و صفحهٔ دوم تولید می‌کند. از فایل JPEG، فونت و `yasin.json` موجود در پروژه استفاده می‌کند. خروجی `docs/previews/pistachio-preview.png` یک **پیش‌نمایش طراحی** است؛ اسکرین‌شات Android نیست.
- `tools/preview.html`: مسیر تصویر، برش‌های کادر، رفتار عنوان و ترتیب کنترل‌ها با طرح جدید هماهنگ شدند.
- متن ۸۳ آیه، فایل‌های زمان‌بندی کلمات، دانلود اختیاری صوت و ساختار فهرست ۱۱۴ سوره تغییر نکرده‌اند.

## بررسی‌های انجام‌شده

- `bash tools/test_core.sh`: ۳۶ assertion هسته و ۱۵ assertion انتقال صوت گذشت.
- `python3 tools/validate_assets.py`: صفر خطای ساختاری؛ ۱۶۶ مورد pending مورد انتظار شامل ۸۳ MP3 اختیاری و ۸۳ زمان‌بندی بررسی‌نشده.
- `python3 -m unittest discover -s tests -v`: ۷ تست موفق.
- `python3 tools/check_apk.py`: محتوای خواندن و تصویر جدید داخل APK هستند و MP3 یا فایل ناقص همراه APK نیست.
- ساخت و lint اندروید API 35 با JDK 17 انجام شد. در محیط محلی به‌دلیل محدودیت شبکه، AAPT2 نصب‌شده در Android SDK با `-Pandroid.aapt2FromMavenOverride=.../aapt2` استفاده شد؛ گردش‌کار GitHub Actions از نصب عادی استفاده می‌کند.
- کد JavaScript پیش‌نمایش با `node --check` بررسی شد؛ تصویر سه‌حالته با WeasyPrint و PyMuPDF تولید و چشمی بازبینی شد. `git diff --check` نیز باید پیش از commit نهایی تأیید شود.

## بازبینی روی دستگاه

اجرای واقعی روی گوشی/شبیه‌ساز در این محیط ممکن نبود. روی یک گوشی باریک و یک گوشی بلند، صفحهٔ اول و دوم، رفت‌وبرگشت صفحه، تغییر اندازهٔ فونت سیستم، حالت تمام‌صفحه، اسکرول متن، دکمه‌های پلیر، و فهرست سوره‌ها را بررسی کنید. قلم قرآنی و شمارهٔ آیات نیز پیش از انتشار باید با مصحف مرجع به‌صورت انسانی تطبیق داده شوند. امضای APKهای debug حاصل از اجراهای جداگانهٔ CI ممکن است یکسان نباشد؛ برای ارتقای نصب موجود باید فرایند امضای پایدار تعریف شود.
