# به‌روزرسانی قاب پسته‌ای و دریافت صوت

## تغییرات

- در نسخهٔ جدید قاب ارسالی، کادر بالای صفحهٔ اول بسم‌الله و شمارهٔ صفحه را نشان می‌دهد؛ از صفحهٔ دوم به بعد نام سوره و شمارهٔ صفحه را نشان می‌دهد. دکمهٔ فهرست و «بیشتر» زیر قاب عنوان‌اند. کادر پایین برای ابزار صفحه، وضعیت و پلیر است.
- فونت Scheherazade New با پوشش علائم متن؛ ۱۰ صفحهٔ ثابت جدید. متن آیات و دادهٔ پیشرفت تغییر نکرده‌اند.
- فهرست ۱۱۴ سوره و ۳۰ جزء با جستجوی فارسی/عربی؛ مطالعه فعلاً برای یاسین فعال است. انتخاب سورهٔ غیرفعال پیام روشن می‌دهد.
- دریافت اختیاری یک آیه یا کل یاسین از EveryAyah؛ ذخیره در فضای خصوصی برنامه. دانلود در پس‌زمینه متوقف می‌شود؛ تلاش بعدی، فایل‌های کامل را دوباره نمی‌گیرد.
- APK صوت MP3 ندارد، حتی اگر MP3های مرجع در پوشهٔ assets روی سیستم توسعه باقی مانده باشند. فایل‌های محلی پاک نمی‌شوند.
- پخش و انتخاب آیه کار می‌کند؛ هایلایت هم‌زمان کلمات به JSON زمان‌بندی تأییدشده نیاز دارد.

## EveryAyah

لینک مستقیم آیهٔ اول: https://everyayah.com/data/Alafasy_64kbps/036001.mp3 . الگو `SSSAAA.mp3` است؛ برنامه برای ۸۳ آیهٔ یاسین شمارهٔ سورهٔ 036 و شمارهٔ آیهٔ سه‌رقمی می‌سازد. API key، سرور واسط یا API جداگانه نیاز نیست. اینترنت هنگام دریافت لازم است؛ فایل کامل در دفعات بعد آفلاین استفاده می‌شود. فایل 036000 مقدمهٔ جداگانه است و در ۸۳ آیه دانلود نمی‌شود.

بخش Quran Text سایت، تصویر GIF آیات دارد: https://everyayah.com/data/QuranText/ . این خروجی جای متن Unicode قابل جستجو و هایلایت نیست. API متنی مستقل مانند https://alquran.cloud/api وجود دارد؛ متن فعلی یاسین از همان منبع ارسالی کاربر و داخل برنامه باقی مانده است. تعویض رسم‌الخط باید جداگانه بررسی شود.

## انتقال به GitHub

پیش‌نمایش طراحی در `docs/previews/pistachio-preview.png` و مشخصات قاب و فونت در `ASSETS.fa.md` هستند. دستورهای زیر برای تغییرات بعدی یا انتقال همین فایل‌ها از clone محلی‌اند؛ اگر تغییرات روی GitHub موجودند، فقط pull لازم است.

پس از آنکه فایل‌های تغییرات در clone محلی شما قرار گرفتند، از ریشهٔ پروژه:

```bash
git status --short
git diff --check
git add .gitignore .github/workflows/android.yml README.md app docs tools tests
git diff --cached --stat
git diff --cached --name-only
```

خروجی دستور آخر نباید فایل `.mp3` داشته باشد. `.gitignore` جدید فایل‌های صوتی دانلودشدهٔ قبلی را نادیده می‌گیرد. اگر قبلاً خودتان MP3 را stage یا commit کرده‌اید، ابتدا وضعیت آن را بررسی کنید؛ این دستورها هیچ فایل صوتی محلی را حذف نمی‌کنند.

پس از بررسی فایل‌های stage‌شده:

```bash
git commit -m "Add pistachio reader, surah index and optional audio downloads"
git push origin main
```

اگر این تغییرات را دستیار مستقیماً روی GitHub فرستاد، در مک فقط `git pull --ff-only origin main` لازم است. روی تغییرات محلی ناسازگار force/reset اجرا نکنید.

Push گردش‌کار `Android development build` را اجرا می‌کند. در اجرای موفق، از Artifacts فایل `hefze-yasin-debug` را دانلود و از ZIP خارج کنید.
