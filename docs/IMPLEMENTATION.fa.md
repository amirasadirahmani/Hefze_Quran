# تصمیم‌های پیاده‌سازی و وضعیت واقعی

## اصلاح پروپوزال

یاسین سورهٔ ۳۶ با ۸۳ آیه است؛ فایل‌های صوت 036-001 تا 036-083 هستند. محتوای کاربر، نه متن تولیدشده توسط مدل، مبنای داده است. رونوشت آیه‌به‌آیه در `docs/yasin-user-source.txt` حفظ شده است. فاصله‌های بین واژه‌ها یکسان شده‌اند؛ علامت ضرب قبل از آیهٔ ۶۰ و نشانهٔ منفرد `ـۚ` در آیهٔ ۵۲ از متن نمایشی حذف شده‌اند تا کلمهٔ تلاوت فرض نشوند. نشانهٔ وقف قبل از آن در آیهٔ ۵۲ باقی مانده است. هیچ جایگزینی با رسم‌الخط منبع دیگر انجام نشده؛ صحت نهایی رسم‌الخط و تصمیم دربارهٔ علائم وقف باید توسط بازبین قرآن تأیید شود.

## معماری

Android native، Java 17 و APIهای خود Android، بدون وابستگی runtime خارجی. رابط فارسی و کنترل‌های استاندارد سیستم؛ متن قرآن با Scheherazade New 4.500 بسته‌بندی‌شده. SQLite شامل تنظیمات، نشان حفظ و موعد مرور و جلسات است. مجوز اینترنت برای دریافت اختیاری صوت وجود دارد؛ مجوز میکروفون وجود ندارد؛ backup ابری سیستم غیرفعال است.

موتور `PlaybackQueue` مستقل از Android است. وضعیت‌ها شامل idle/loading/playing/gap/paused/finished/error است. هر load شناسهٔ نسل جدید می‌گیرد؛ callbackهای فایل قبلی پس از جابه‌جایی رد می‌شوند. سکوت با ساعت monotonic اجرا می‌شود. شروع/پایان هر فایل در MediaPlayer به ماشین حالت گزارش می‌شود. یک ticker مرکزی با فاصلهٔ حدود ۱۰۰ms هم صف و هم هایلایت را به‌روز می‌کند؛ در پس‌زمینه متوقف می‌شود.

زمان‌بندی هنگام بارگذاری در worker بررسی می‌شود؛ hash، هویت آیه، متن و مرزها باید معتبر باشند. بولدکردن متغیر استفاده نشده تا عرض کلمه تغییر نکند؛ foreground و background رنگ می‌گیرند و هندسه ثابت می‌ماند. متن هر سطر با StaticLayout راست‌به‌چپ شکل می‌گیرد و یک Span برای هر محدودهٔ کلمه به کار می‌رود.

صفحه‌های اختصاصی در JSON، با شناسهٔ `yasin-app-v2-scheherazade`، ابعاد مرجع 760×1072، ۱۱ سطر و فونت ثابت ذخیره شده‌اند. در گوشی فقط Canvas مقیاس می‌شود و صفحه در ارتفاع کم قابل اسکرول است. حالت تمام‌صفحه کنترل‌ها و نوارهای سیستم را پنهان می‌کند؛ نمایش transient نوارها با swipe امکان‌پذیر است. تعیین ابعاد و مختصات واقعی وابسته به فونت و Android است؛ QA نهایی روی گوشی لازم است. این صفحه‌ها صفحات رسمی مصحف چاپی خاصی نیستند.

## محدودیت‌های مشخص

- صوت واقعی با درخواست کاربر از EveryAyah دانلود می‌شود؛ alignment تأییدشده هنوز موجود نیست؛ هایلایت کلمات با دادهٔ تولیدی یا تخمینی شبیه‌سازی نشده است.
- وضعیت دقیق ساخت و آزمون نسخهٔ جدید در `TEST_REPORT.md` ثبت شده است. نصب و آزمون روی گوشی واقعی هنوز باید انجام شود.
- نمونهٔ بصری سطرها با همان فونت و Pillow بازبینی شده؛ این آزمون، screenshot اپلیکیشن یا تأیید Android rendering نیست.
- ارزیابی حفظ، امتیاز تلفظ، ضبط صدا، ترجمه و موضوع‌بندی خارج از دامنه‌اند. روش‌ها تنها پیش‌فرض‌های همان مسیر تمرین را تنظیم می‌کنند.
- قاری ثابت مشاری العفاسی، EveryAyah 64kbps است. فایل دانلودی در فضای خصوصی برنامه نگهداری و پس از دریافت کامل و بررسی decoder منتشر می‌شود. MP3های پوشهٔ assets از APK حذف می‌شوند؛ فایل محلی توسعه‌دهنده پاک نمی‌شود.
- یادآوری غیر دقیق، محلی و نیازمند اجازهٔ اعلان است؛ مجوز exact alarm و receiver بوت ندارد. برنامه پس از reboot باید باز شود. مرور فاصله‌دار فعلاً فقط «فردا» است، نه الگوریتم پیشرفتهٔ SRS.
- موقعیت صوت بعد از خروج ذخیره می‌شود؛ شمارهٔ تکرار و باقی‌ماندهٔ مکث پس از مرگ فرایند حفظ نمی‌شوند. پایگاه دادهٔ پیشرفت حذف نمی‌شود.
- مقدار زمان شنیدن تقریباً از زمان monotonic هنگام playing جمع می‌شود و زمان سکوت حذف است؛ این اندازه‌گیری telemetry دقیق نمونه‌به‌نمونهٔ decoder نیست.
- ابزار هم‌ترازی دستی آماده است. هم‌ترازی اجباری خودکار به انتخاب مدل و بررسی کیفیت روی صوت قاری نیاز دارد و هنوز اجرا نشده است.

`StudyStore` اکنون فقط schema نسخهٔ ۱ دارد؛ `onUpgrade` در نصب این نسخه اجرا نمی‌شود. هنگام ایجاد نسخهٔ ۲ باید migration حفظ‌کنندهٔ داده و آزمون ارتقای پایگاه پرشده از نسخهٔ ۱ اضافه شود. حذف جدول‌ها یا افزودن `ALTER TABLE` بدون تعریف schema آینده راه‌حل معتبری نیست. استفاده از `Activity` استاندارد Android عمدی است تا وابستگی runtime اضافه نشود. VectorDrawable از API ۲۱ پشتیبانی می‌شود و حداقل API برنامه ۲۶ است؛ برنامه تم روشن ثابت دارد و Night Mode خودکار AppCompat را ارائه نمی‌کند. ابزار تولید محتوا در CI با نسخهٔ ثابت Pillow اجرا و خروجی‌اش با JSON ثبت‌شده مقایسه می‌شود.

## تغییر داده یا فونت

JSON تولیدی همراه سورس است؛ ساخت APK به Python نیاز ندارد. فقط برای بازتولید صفحه‌ها از متن، Python با Pillow و پشتیبانی RAQM لازم است:

```bash
python3 -m venv .tools/content-env
source .tools/content-env/bin/activate
python -m pip install -r tools/requirements-content.txt
python tools/generate_content.py
python tools/check_generated_content.py
python tools/validate_assets.py
```

اسکریپت زمان‌بندی موجود را بازنویسی نمی‌کند؛ پس از تغییر متن، validator ناسازگاری alignment قدیمی را گزارش می‌کند. تغییر صفحه‌بندی باید با نسخهٔ جدید `layout.id` منتشر شود تا جای حفظ‌شدهٔ متن بدون اطلاع تغییر نکند.

## دریافت اختیاری و قاب جدید

`AudioDownloads` یک worker ترتیبی برای دانلود دارد. تنها کلیک صریح کاربر دانلود را شروع می‌کند. HTTPS، timeout، محدودیت ۱۰ مگابایت برای هر آیه، بررسی طول پاسخ و بررسی duration با `MediaMetadataRetriever` اعمال می‌شوند. فایل `.part` هرگز برای پخش ارائه نمی‌شود؛ پس از تأیید، با rename در همان پوشه منتشر می‌شود. لغو/خطا فایل کامل قبلی را حفظ می‌کند. دانلود در پس‌زمینه ادامه ندارد و با onPause متوقف می‌شود. درخواست دوباره، آیات کامل را رد می‌کند و آیهٔ ناقص را از ابتدا می‌گیرد؛ HTTP Range resume پیاده نشده است. مسیر ذخیره `files/recitations/alafasy64/036-NNN.mp3` است و پاک‌کردن دادهٔ برنامه یا uninstall آن را حذف می‌کند.

اعتبارسنجی زمان‌بندی SHA-256 روی همان فایل محلیِ انتخاب‌شده برای پخش انجام می‌شود. پس از دانلود، cache نتیجهٔ منفی زمان‌بندی پاک می‌شود. دانلود هیچ‌وقت به‌تنهایی پخش را آغاز نمی‌کند.

فهرست ۱۱۴ سوره فقط metadata است؛ متن/پیشرفت تمام قرآن به مدل داده اضافه نشده است. فقط سورهٔ ۳۶ قابل مطالعه است. دادهٔ فهرست و مرز جزءها از `/v1/surah` و `/v1/meta` سرویس Al Quran Cloud دریافت و در assets ثبت شده‌اند؛ اجرای فهرست به API وابسته نیست.

تعویض فونت تعداد صفحات را از ۶ به ۱۰ تغییر داد. محل مطالعه بر اساس شمارهٔ آیه بازیابی می‌شود؛ schema پایگاه داده تغییر نکرده است. فاصلهٔ بین کلمات برای پرکردن سطر تنظیم می‌شود؛ خود شکل حروف کشیده نمی‌شود. نشان شمارهٔ آیه با ReplacementSpan جداگانه رسم می‌شود.
