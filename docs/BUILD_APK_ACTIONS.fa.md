# ساخت و دریافت APK جدید با GitHub Actions

این روش روی مرورگر مک یا گوشی انجام می‌شود و نیازی به Android Studio، SDK یا Java محلی ندارد.

## ۱. نسخهٔ درست را انتخاب کن

با حساب دارای دسترسی نوشتن به ریپازیتوری وارد GitHub شو. در شاخهٔ `main` فایل `app/build.gradle` باید نسخهٔ `0.8.0` و `versionCode 8` داشته باشد. نسخهٔ آزمایشی با نام بستهٔ `ir.hefze.quran.review08` نصب می‌شود.

## ۲. اجرای ساخت

1. [صفحهٔ Android development build](https://github.com/amirasadirahmani/Hefze_Quran/actions/workflows/android.yml) را باز کن.
2. روی **Run workflow** کلیک کن.
3. در **Branch** گزینهٔ **main** را انتخاب کن.
4. دکمهٔ سبز **Run workflow** را بزن.
5. اجرای تازه را باز کن و منتظر سبزشدن job با نام **verify** بمان. تست‌ها، بررسی دارایی‌ها، build و lint اجرا می‌شوند.

برای گرفتن آخرین تغییرات، اجرای تازه بساز؛ **Re-run jobs** روی اجرای قدیمی همان commit قدیمی را دوباره می‌سازد.

## ۳. دانلود فایل

پایین صفحهٔ همان اجرای موفق، بخش **Artifacts**، روی **hefze-quran-debug** کلیک کن. فایل ZIP را باز کن؛ فایل `app-debug.apk` در پوشه‌های خروجی قرار دارد. می‌توانی با جستجوی نامش در فایل‌های استخراج‌شده پیدایش کنی.

فایل `BUILD_INFO.txt` نیز همراه خروجی است و نسخه، شناسهٔ برنامه، commit، شاخه، لینک اجرا و SHA-256 فایل APK را ثبت می‌کند. Commit باید با اجرای تازهٔ انتخاب‌شده یکی باشد.

## ۴. نصب روی گوشی

فایل APK را به گوشی منتقل کن، بازش کن و در صورت درخواست اجازهٔ نصب از همان فایل‌منیجر را فعال کن. نسخهٔ ۰.۸ کنار نسخه‌های review قبلی نصب می‌شود؛ اشتباهاً نسخهٔ قبلی را باز نکن.

اگر با ADB روی مک تست می‌کنی:

```bash
adb devices
adb install -r "/مسیر/واقعی/app-debug.apk"
adb shell am start -n ir.hefze.quran.review08/ir.hefze.quran.FullQuranActivity
```

USB debugging باید روشن باشد و درخواست اعتماد گوشی را تأیید کنی. `adb devices` باید وضعیت `device` نشان دهد.

اگر `INSTALL_FAILED_UPDATE_INCOMPATIBLE` دیدی، امضای APK با نصب موجود متفاوت است. این خروجی debug است و کلید runner بین اجراها تضمین‌شده و ثابت نیست. حذف نصب داده و صوت همان برنامه را پاک می‌کند؛ برای حفظ آن‌ها قبل از حذف تصمیم بگیر. امضای ثابت release در این تغییر راه‌اندازی نشده است.

## ۵. چک‌لیست تست

- نصب تازه: «شروع مطالعه» به فاتحه، صفحهٔ ۱ برود؛ صرفاً ذخیرهٔ تنظیمات آن را به «ادامه» تبدیل نکند.
- یک سوره باز کن، خارج شو و برگرد؛ ادامهٔ واقعی همان محل را باز کند.
- صفحهٔ تنظیمات کامل، راست‌چین و بدون لینک تمرین یاسین باشد.
- تعداد قرائت را ۲ و مکث را ۳ ثانیه بگذار؛ با صوت آیه‌به‌آیه امتحان کن.
- تصویر دکمهٔ دریافت در صفحه و پنجره دیده شود. بعد از اتمام دانلود، توقف پنهان باشد.
- سمت راست قبل و سمت چپ بعد باشد؛ دکمه‌های صفحه با دکمه‌های آیه اشتباه نشوند.
- در صفحهٔ ۴۴۰ وجود فاطر ۴۵ قبل از یس صحیح است. صفحهٔ بعد ۴۴۱ با یس ۱۳ شروع می‌شود.

## گزارش تست خودکار رابط

[Android UI checks](https://github.com/amirasadirahmani/Hefze_Quran/actions/workflows/android-ui.yml) workflow جداگانه‌ای برای شبیه‌ساز اندروید است. artifactهای `android-ui-api-26` و `android-ui-api-35` شامل گزارش تست و تصویر هستند، نه APK قابل نصب. برای ساخت برنامه همان **Android development build** را اجرا کن.

## اگر مشکلی پیش آمد

- نبودن Run workflow: وارد حساب مالک شو و همان workflow بالا را باز کن؛ فایل workflow باید روی شاخهٔ پیش‌فرض باشد.
- قرمزشدن verify: مرحلهٔ قرمز را باز کن و خطای آن را ارسال کن. خروجی اجرای شکست‌خورده را به‌عنوان نسخهٔ سالم نصب نکن.
- نبودن Artifacts: منتظر پایان موفق اجرا بمان؛ وارد GitHub باش. خروجی‌های منقضی‌شده را با اجرای تازه جایگزین کن.
- تغییری در برنامه نمی‌بینی: commit داخل BUILD_INFO و شناسهٔ برنامهٔ اجراشده را بررسی کن.

منبع رسمی: [اجرای دستی workflow](https://docs.github.com/en/actions/how-tos/manage-workflow-runs/manually-run-a-workflow) و [دریافت artifacts](https://docs.github.com/en/actions/managing-workflow-runs/downloading-workflow-artifacts).
